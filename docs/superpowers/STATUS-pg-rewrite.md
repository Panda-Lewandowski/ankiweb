1. `field_at_index(flds, idx)` — split on `\x1f`, nth field. *Trivial/exact* (`split_part`).

## M3 plan (pattern CONFIRMED by the M2.4 slice `57b232c9a`)
**Decision: Approach A** (explicit per-method PG impls). The slice proved it clean; B (rusqlite/postgres abstraction) rejected (silent-corruption risk vs the equivalence goal).

**The confirmed PgStorage method pattern (template for the remaining ~195 ports):**
- `PgStorage { client: RefCell<postgres::Client> }` — `RefCell` (not Mutex) because a `Collection` is single-threaded (shared instances are Mutex-wrapped); mirrors rusqlite's interior mutability so methods stay `&self`. Each statement: `self.client.borrow_mut().execute/query/query_one(SQL, &[&p…])`.
- `$1..$n` placeholders (not `?`); `last_insert_rowid()` → `INSERT … RETURNING id` read via `query_one(...).get(0)`; `INSERT OR REPLACE` → `INSERT … ON CONFLICT (pk) DO UPDATE SET c = excluded.c`; the id-collision `CASE WHEN $1 IN (SELECT id…) THEN max(id)+1 ELSE $1 END` preserved verbatim.
- Every integer column is `bigint` → read as `i64`, cast to the Rust target (`Usn(row.get::<_,i64>(i) as i32)`, `ord as i64`/`as u32`). Protobuf configs ↔ `bytea` via prost `.encode()/.decode(&blob[..])` (reused unchanged).
- Standalone row decoders `fn pg_row_to_X(row: &postgres::Row) -> Result<X>` mirror the rusqlite `row_to_X`.
- **BORROW HAZARD (codify):** `self.client.borrow_mut().query(…)?.iter().map(|r| …)` is safe ONLY if the mapper makes no further DB call. If it must, bind first: `let rows = self.client.borrow_mut().query(…)?;` (releases the `RefMut` at the `;`), then process `rows`. A re-borrow while the `RefMut` is live panics.
- **Per-test isolation:** build PG collections with DSN suffix `options=-csearch_path=<unique_schema>`; an admin conn `CREATE SCHEMA`/`DROP SCHEMA … CASCADE` around each test.
- **Transactions (confirmed in note/card slice `f23608a57`):** SQLite's `SAVEPOINT rust` implicitly opens a tx in autocommit and the outermost `RELEASE rust` commits it; PG forbids savepoints outside a tx. So `PgStorage` carries `tx_depth: Cell<u32>` (0 = autocommit), brackets the OUTERMOST savepoint with explicit `BEGIN`/`COMMIT`, and `is_autocommit()` = `depth==0`. SQLite's single-writer `BEGIN EXCLUSIVE` (`begin_trx`) → plain `BEGIN` (PG MVCC, no exclusive lock — this is the M4 single-writer removal already starting here). `cards.data`/`notes` JSON cols are **text** (CardData `convert_to_json`/`from_str`), not blob. `CardType`/`CardQueue` rebuilt from `bigint` via `TryFromPrimitive`.

> ⚠️ **UNICASE ORDERING HAZARD (live; framework refined across deck + notetype slices).** ICU `und-u-ks-level2` (the `unicase` backing) is NOT byte-equivalent to Anki's `UniCase` (case-folded code-point): ICU treats `\x1f` (the name separator) and other control chars as fully-ignorable. **The rule, by query kind:**
> - **Equality / uniqueness** (`WHERE name = $1`, UNIQUE) → `COLLATE unicase` (correct: case-insensitive dedup, exactly UniCase's intent).
> - **Prefix/child RANGE crossing `\x1f`** (deck tree) → `COLLATE "C"` — but ONLY where the in-range rows share one canonical case (deck children carry the parent's case, guaranteed by the unique-under-unicase index), so code-point order == UniCase order there.
> - **Sorted LISTING** (`ORDER BY name`) → **keep `COLLATE unicase`** (NOT `"C"` — `"C"` is case-SENSITIVE and mis-orders e.g. "banana" vs "Basic"). ICU == UniCase for all control-char-free names (the realistic case for deck/notetype/field/tag names); divergence only on ICU-ignorable control chars.
> - **BINARY columns** (`config.key`, uncollated in SQLite) → `COLLATE "C"` (exact byte order).
> 
> Residual control-char divergence in the two range/sort cases → **exact fix = a pgrx fold-key fn** (UniCase's case-folded code-point key; `ORDER BY`/range/UNIQUE on it) — do in M2.3b/M2.3-collation. Differential tests MUST include mixed-case (+ ideally control-char) names so divergence surfaces.
